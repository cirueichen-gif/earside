# Presets（遊戲預設）

一個 preset = 一個遊戲的「看哪裡＋怎麼判斷」。座標是**相對遊戲視窗客戶區**的 `[x, y, w, h]`（0–1）。

## 欄位

| 欄位 | 意思 |
|---|---|
| `id` / `name` | 識別與顯示名稱 |
| `game_type` | 自由字串：`fps`／`rts`／`moba`／`demo`……只是給人看與分類 |
| `enabled` | 這個 preset 要不要跑（false＝`watch` 直接跳過） |
| `sensitivity` | 這個遊戲的預設靈敏度（0.25–4.0，越高越容易觸發） |
| `match.window_title_regex` | 找哪個視窗（不分大小寫） |
| `regions[]` | 每個區域：`rect`、`interval_ms`、`rule` |
| `triggers[]` | 事件→動作（P3 才接） |

區域的 `rule` 也可以單獨寫 `sensitivity`，覆蓋 preset 的值。

## 為什麼要分遊戲類型

- **FPS**：小地圖、自己的名字、擊殺訊息；畫面變化快，但區域小、規則單純。
- **RTS**：資源條、小地圖、選取面板；**UI 一直有小動畫**，用 `change` 很容易誤報 → 靈敏度往 0.8 以下調、`consecutive` 加大、interval 放慢。
- **MOBA**：技能冷卻、擊殺提示；顏色/模板比變化可靠。
- 其他類型：先從「你死了會變什麼」和「你會想被提醒什麼」兩個區域開始，不要一次框十個。

## 靈敏度怎麼調

- `sensitivity` 越高＝門檻越寬鬆＝越容易觸發（造型、特效多時往 0.5–0.8 調）。
- 太低→該報的不報；太高→一直報。先看 `watch` 乾跑的事件量，再調。
- 每個區域還能再覆蓋一次（`rule.sensitivity`）。

## 現成範例

- `demo-color.json`：配 `tests/_color_window.py` 的換色視窗，純測試。
- `example-rts.json`：RTS 的資源條／小地圖／選取面板，座標要自己改。

## 分享規則（給之後的貢獻者）

只收座標＋規則＋台詞，**不要上傳遊戲截圖或素材**（版權，而且會過時）。模板圖由使用者自己截。
